# Добавление тестового заказа для проверки карточки и шевронового процесса

Этот план описывает шаги по добавлению полноценного тестового заказа в базу данных `database.db` проекта `PartsOps AI Manager` для верификации карточки заказа, шевронового процесса меню и сквозного флоу обработки без использования заглушек.

> [!IMPORTANT]
> Для верификации процесса потребуется запустить бэкенд FastAPI и фронтенд React на локальной машине. В плане предложено автоматическое тестирование через `browser_subagent`.

## Proposed Changes

Мы добавим вспомогательный скрипт на Python, который добавит тестовый заказ напрямую в SQLite базу данных `partsops-ai-manager/database.db`.

### [NEW] [add_test_order.py](file:///Users/user/projects/Danila%20master/partsops-ai-manager/scripts/add_test_order.py)

Скрипт создаст заказ со следующими параметрами:
- **ID заказа:** `REQ-TEST8888`
- **Клиент:** `Данила Мастер`
- **Источник:** `telegram`
- **Статус:** `NEW` (начальный этап Входящая / INTAKE)
- **Приоритет:** `urgent` (Срочный)
- **Детали (parts_json):**
  1. `Тормозные колодки передние BMW X5 (E70)` (quantity: 1)
  2. `Масляный фильтр BMW N55/N57` (quantity: 2)
  Эти детали выбраны специально, так как для них в базе данных (`SEED_CATALOG`) есть реальные предложения поставщиков (`TRW`, `Ate`, `Brembo`, `Mann`, `Bosch`). Это позволит проверить шаг «Метчинг» (Шаг 3) с подбором реальных цен и поставщиков без заглушек.

- **Данные авто:**
  - VIN: `WBAKS410X0L******`
  - Марка/Модель: `BMW X5`
  - Год: `2016`

## Verification Plan

### Automated Steps
1. Запуск скрипта добавления заказа:
   ```bash
   python3 partsops-ai-manager/scripts/add_test_order.py
   ```
2. Проверка наличия заказа в базе данных через SQLite запрос.
3. Запуск бэкенда и фронтенда через `start.sh` (в фоновом режиме).
4. Запуск `browser_subagent` для симуляции действий пользователя в браузере:
   - Открыть `http://localhost:5173`.
   - Найти в правой боковой панели «Активная очередь» заказ `REQ-TEST8888` (Данила Мастер) и кликнуть на него.
   - Проверить отображение карточки заказа и шеврона (этап «Входящая»).
   - Нажать кнопку «Подтвердить нормализацию» на Шаге 2. Статус должен перейти в `MATCHING`.
   - Перейти на Шаг 3 («Метчинг»). Выбрать предложения поставщиков для обеих деталей.
   - Перейти на Шаг 4 («Согласование»). Проверить цепочку аудита и нажать кнопку «Явно одобрить закупку». Статус перейдет в `APPROVED`.
   - Перейти на Шаг 5 («Прайсинг»). Убедиться в корректности расчета цены, наценки и генерации черновика счета (Invoice Preview) без заглушек.
5. Синхронизация изменений с Obsidian Vault через `bash scripts/sync_obsidian.sh`.
