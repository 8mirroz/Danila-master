# Система скрапинга и поиска артикулов PartsOps

> **Цель:** Отчёт описывает архитектуру, компоненты и правила использования скрапинг-системы для эффективного поиска и подбора автозапчастей по артикулам.

---

## 1. Общая архитектура

```
articles.txt          →   Crawler (my-crawler/)    →   aggregated_parts.csv/json
(список артикулов)         exist.ru / autodoc.ru /        (сырые цены с площадок)
                           rossko.ru
    
        ↓
        
  matcher.py           →   База поставщиков  (suppliers.py)
  (6-компонентный            SupplierCatalogItem (14шт)
   фаззи-матчер)             Supplier (5 поставщиков)
  
        ↓
        
  Результат: список деталей со скорами,
  разбивкой по компонентам и отклонением
  цены от медианы
```

Система состоит из двух независимых частей:

| Часть | Назначение | Технологии |
|-------|-----------|------------|
| **Crawler** (`my-crawler/`) | Сбор реальных цен с маркетплейсов | Playwright (Crawlee) |
| **Matcher** (`partsops-ai-manager/matcher.py`) | Поиск по каталогу поставщиков + фаззи-скоринг | RapidFuzz, Levenshtein, Jaro-Winkler, Cosine |

## 2. Краулер (my-crawler/)

### 2.1 Входные данные: `my-crawler/articles.txt`

Файл содержит список артикулов для поиска — по одному на строку. Строки, начинающиеся с `#`, игнорируются.

**Пример:**
```
34116852253
04465-33471
90915-YZZD4
# Это комментарий, будет пропущен
11427953129
```

### 2.2 Запуск

```bash
cd my-crawler
python -m my_crawler.main
```

Краулер открывает **браузер (не headless)** — это важно для прохождения антибот-защиты. Можно вручную решить капчу или войти в аккаунт, если потребуется.

### 2.3 Площадки и хендлеры

Для **каждого** артикула из `articles.txt` краулер создаёт 3 запроса:

#### Exist.ru (`handle_exist`)
- URL: `https://www.exist.ru/Price/?pcode={article}`
- Логика:
  1. Проверяет, есть ли на странице каталоги (категории деталей) — если да, добавляет их в очередь
  2. Если это уже страница с ценами — парсит `.row-container`, извлекает:
     - Бренд
     - Артикул (партномер)
     - Описание
     - Сроки доставки
     - Цену (очищает от мусора через `clean_price`)
- **Особенность:** Собирает все строки (оригинал + аналоги) в одном цикле

#### Autodoc.ru — поиск (`handle_autodoc`)
- URL: `https://www.autodoc.ru/#search-{article}`
- Логика:
  1. Находит видимое поле поиска (eval JS)
  2. Печатает артикул с задержкой (100ms между символами)
  3. Кликает кнопку поиска
  4. Ждёт выпадающий список
  5. Извлекает все ссылки вида `/price/...` — добавляет их в очередь с лейблом `autodoc_price`

#### Autodoc.ru — цена (`handle_autodoc_price`)
- Парсит карточку товара:
  - Цена (`.card__price-link`) 
  - Наличие (`.card__price-stock`)
  - Доставка (`.card__delivery-item`)
  - Хлебные крошки (уточняют бренд)
  - Заголовок `h1` (описание)

#### Rossko.ru (`handle_rossko`)
- URL: `https://sochi.rossko.ru/search?q={article}&text={article}`
- Логика:
  1. Ждёт загрузки результатов
  2. Ищет ссылки с классом `result-item-...` и `link`
  3. Для каждой ссылки извлекает:
     - Бренд (класс `brand__...`)
     - Артикул (класс `articleNumbers__...`)
     - Описание (полный текст минус бренд/артикул/цена)
     - Цену (класс `priceWrapper__...` или `price__...`)
     - Доставку (класс `delivery__...` или `deliver__...`)

### 2.4 Результаты краулера

Сохраняются в `my-crawler/results/`:
- `aggregated_parts.csv` — табличный формат
- `aggregated_parts.json` — структурированный JSON

**Поля записи:**
```json
{
  "site": "exist.ru",
  "search_article": "34116852253",
  "brand": "TRW",
  "article": "34116852253",
  "description": "Тормозные колодки передние BMW X5",
  "delivery": "1-2 дня",
  "price": "4500 ₽"
}
```

## 3. Матчер (matcher.py)

### 3.1 Назначение

Сопоставляет текстовый запрос (название детали, бренд, OEM, автомобиль) с каталогом поставщиков (`SupplierCatalogItem`) в БД и возвращает отсортированный список совпадений с весовыми скорами.

### 3.2 6-компонентная формула скоринга

Итоговый score = взвешенная сумма 6 компонентов:

| # | Компонент | Вес | Описание |
|---|-----------|-----|----------|
| 1 | **OEM Score** | 30% | Если в запросе есть число ≥5 цифр — точное совпадение OEM номера (100) или 0 |
| 2 | **Brand/Article Score** | 20% | Если в запросе есть известный бренд — проверка совпадения бренда товара (fuzz.WRatio) |
| 3 | **Text/Name Score** (ансамбль) | 20% | Комбинация Levenshtein (25%) + Jaro-Winkler (35%) + Cosine (40%) |
| 4 | **Vehicle Compatibility** | 15% | Если в запросе упомянут автомобиль — проверка, есть ли он в названии детали |
| 5 | **Side Position** | 10% | Если в запросе сторона (перед/зад/лев/прав) — проверка в названии |
| 6 | **Supplier/Data Score** | 5% | `reliability_score` поставщика (0.0–1.0) |

### 3.3 Cross-brand penalty (штраф)

Если в запросе найден `vehicle_keyword` (например, "BMW"), а у детали `vehicle_score == 0` (автомобиль не совпадает), итоговый score **уменьшается на 35 баллов**.

Это жёсткий фильтр: Toyota Camry с BMW в запросе получит score < 50 и, скорее всего, не попадёт в топ-3.

### 3.4 Ключевые слова (контролируемые списки)

**`vehicle_keywords`:**
```
x5, camry, bmw, toyota, audi, mercedes, urus, lamborghini
```

**`side_keywords` (стороны):**
```
передн, задн, левы, прав, front, rear, left, right
```

**`synonym_map` (рус → англ синонимы):**
```
колодки   → pads, pad, brake
фильтр    → filter, mann, bosch
свечи     → spark, ngk
диск      → disc, rotor, brembo
амортизатор → shock, absorber, bilstein
масло     → oil, castrol
```

**`known_brands` (известные бренды для Brand Score):**
```
trw, ate, ngk, brembo, bosch, mann, akebono, toyota, castrol, bilstein
```

### 3.5 Параметры

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `threshold` | 55.0 | Минимальный score для включения в результаты |
| `limit` | 5 | Максимальное количество результатов |
| `vehicle_context` | None | Контекст автомобиля (например, "BMW") — добавляется к запросу для улучшения Vehicle Score |
| `tenant_id` | None | Фильтр по тенанту |

### 3.6 Дополнительные вычисления

- **Медианная цена** — для топ-N результатов вычисляется медиана, и каждый результат получает `price_deviation_from_median`
  - `(price - median) / median`
  - Отрицательное значение = дешевле медианы

### 3.7 Пример работы матчера

**Запрос:** `"Тормозные колодки передние BMW X5"`

Ожидаемый результат:
```
1. Тормозные колодки передние BMW X5 (E70) — TRW — 4500₽  — score: 94.2
   Breakdown: OEM:100, Brand:100, Text:89, Vehicle:100, Side:100, Supplier:92
   
2. Тормозные колодки передние BMW X5 — Ate — 3900₽ — score: 87.5
   Breakdown: OEM:100, Brand:87, Text:82, Vehicle:100, Side:100, Supplier:87

3. Тормозные колодки задние BMW X5 (E70) — TRW — 3800₽ — score: 82.1
   Breakdown: OEM:0, Brand:100, Text:75, Vehicle:100, Side:100, Supplier:92
```

## 5. Практические рекомендации: как правильно искать артикулы

### 5.1 Общие правила формулировки запроса

| Хотите найти... | Пишите в запросе... | Почему работает |
|----------------|--------------------|-----------------|
| По OEM-номеру | `34116852253` | OEM Score (30%) даст 100, деталь будет наверху |
| По бренду + детали | `Тормозные колодки TRW` | Brand Score (20%) + Text Score (20%) |
| Конкретный авто | `Колодки BMW X5 передние` | Vehicle Score (15%) + Side Score (10%) |
| Максимальная точность | `34116852253 TRW передние BMW X5` | Все 6 компонентов работают одновременно |

### 5.2 Приоритеты и чувствительность

1. **OEM-номер — самый сильный сигнал (30%)**
   - Если в запросе есть число ≥5 цифр — матчер считает, что это OEM, и включает точную проверку
   - Если OEM совпал → сразу 30% к финальному score
   - Если OEM не совпал → 0% по этому компоненту
   - **Вывод:** Всегда указывайте OEM, если он известен

2. **Vehicle Context — повышает точность (15%)**
   - Параметр `vehicle_context` (например, `"BMW"`) принудительно добавляется в запрос
   - Если деталь не подходит к указанному авто — штраф -35 баллов + Vehicle Score = 0
   - **Вывод:** Используйте `vehicle_context` для фильтрации по марке

3. **Известные бренды — дополнительный фильтр (20%)**
   - Если в запросе есть бренд из `known_brands` — проверяется его совпадение с каталогом
   - Неизвестные бренды игнорируются (Brand Score = 100, не влияет)
   - **Вывод:** Указывайте бренд, если хотите отсеять неподходящие аналоги

4. **Сторона (перед/зад/лев/прав) — уточнение (10%)**
   - Если указали сторону, но у детали её нет или другая сторона → Position Score = 0
   - **Вывод:** Добавляйте сторону для точного подбора

5. **Текстовое совпадение (20%) — ансамбль из 3 алгоритмов**
   - Работает на очищенных строках (без спецсимволов)
   - Cosine-схожесть (40%) хорошо ловит совпадения по ключевым словам
   - Jaro-Winkler (35%) устойчив к опечаткам
   - Levenshtein (25%) — классическое расстояние редактирования

### 5.3 Примеры запросов и ожидаемое поведение

**Пример 1: Поиск по OEM**
```
Запрос: "34116852253"
→ OEM Score = 100% (совпало с CAT-001, CAT-005, CAT-013)
→ Текстовая часть слабая ("34116852253" vs "Тормозные колодки...") — Text Score низкий
→ Vehicle/Brand/Side — нейтрально (нет упоминаний)
→ Итог: детали с этим OEM наверху, остальные — ниже
```

**Пример 2: Поиск с указанием автомобиля**
```
Запрос: "Тормозные колодки BMW"
→ Vehicle Score = 100 для деталей с "bmw" в названии
→ Toyota Camry (CAT-008) получает Vehicle Score = 0 и штраф -35
→ Результат: только BMW-совместимые детали
```

**Пример 3: Полный запрос (максимальная точность)**
```
Запрос: "34116852253 TRW передние тормозные колодки BMW X5"
→ OEM: 100 (34116852253)
→ Brand: 100 (TRW)
→ Text: ~85-95
→ Vehicle: 100 (BMW/X5)
→ Side: 100 (передние)
→ Supplier: varies
→ Итоговый score: ~91-95
```

### 5.4 Интеграция краулера и матчера

Полный цикл поиска артикула:

1. **Краулер** собирает цены с exist/autodoc/rossko в `results/aggregated_parts.csv`
2. Человек (или агент) смотрит на собранные данные и **формулирует запрос** для матчера
3. **Матчер** ищет в каталоге поставщиков, используя:
   - OEM из результатов краулера (если найден)
   - Бренд из результатов краулера
   - Описание детали
   - Vehicle context (марка авто) — задаётся дополнительно
4. Результат — топ-5 деталей с ценами, скорами и отклонением от медианы

### 5.5 Тонкие настройки

#### Порог срабатывания (`threshold`)
- **55.0** (по умолчанию) — сбалансированный режим
- **70.0+** — только очень уверенные совпадения (меньше шума, но можно пропустить)
- **30.0–40.0** — либеральный режим (больше результатов, но ниже точность)

#### Лимит результатов (`limit`)
- **5** (по умолчанию) — достаточно для выбора лучшего предложения
- **10+** — для сравнительного анализа цен

### 7.3 ✅ Synonym boost в Text Score

**Новая функция:** `cosine_sim_with_synonyms(a, b, synonym_map)`

Заменяет старую `cosine_sim` в Text Score. Принцип работы:
1. Берёт токены запроса (например, "колодки")
2. Проверяет каждый токен на вхождение ключей из `synonym_map` (например, "колодк" в "колодки")
3. Добавляет английские синонимы (pads, pad, brake) в вектор запроса
4. Вычисляет cosine similarity с учётом расширенных токенов

**Эффект:** запрос "тормозные колодки BMW" теперь лучше находит детали с описанием "brake pads BMW", даже если в названии нет русского слова "колодки".

- Автоматическое создание поставщика `SUP-CRAWLER` (или привязка к существующему через `--supplier-id`)
- Дедупликация по `(site, article, brand)` — повторный запуск не создаёт дубликатов
- Парсинг цен из строк ("4 500 ₽" → 4500.0)
- Эвристическое определение остатков и сроков доставки
- Автоматическая категоризация деталей (brake, filter, oil, ignition, suspension, sensor и т.д.)
- Режим `--dry-run` для предварительного просмотра

**Использование:**
```bash
# Предпросмотр
python -m scripts.import_crawler_results --dry-run

# Реальный импорт
python -m scripts.import_crawler_results

# Импорт с привязкой к конкретному поставщику
python -m scripts.import_crawler_results --supplier-id SUP-001
```

## 8. Известные ограничения

1. **Краулер требует ручного вмешательства при антибот-защите**
   - Даже с headless-режимом exist/autodoc/rossko могут блокировать запросы
   - Для production рекомендуется использовать proxy-ротацию и эмуляцию человеческого поведения

2. **Категоризация в скрипте импорта — эвристическая**
   - `categorize_part()` использует простой keyword matching
   - Для точной категоризации можно подключить LLM

3. **Нет автоматического запуска импорта после краулера**
   - Скрипт импорта нужно запускать вручную или добавить в CI/CD pipeline
   - Можно интегрировать как post-crawl hook в будущем
